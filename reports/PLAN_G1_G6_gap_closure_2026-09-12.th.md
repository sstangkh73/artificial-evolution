## 3. G1 — lure ไม่มีต้นทุนทางนิเวศที่วัดได้

### 3.1 อาการและหลักฐานในเอกสาร

Study 2 ทั้งหมดรันใน harness ควบคุม (`SimpleNamespace`) ที่:

- agent ถูกรีเซ็ตให้ **อิ่มก่อนทุกโอกาส** (กันไม่ให้ความหิวบังคับให้กิน)
- **ไม่มีการตาย ไม่มีการสืบพันธุ์ ไม่มีการเดิน ไม่มีการแย่งอาหาร**
- ตัวแปรตามคือ "ร้อยละของ agent ที่ค่าผลไม้สุดท้าย > ค่าอาหารหลัก"

`SUBMISSION_BLOCKERS.md` จึงสั่งห้ามไว้ชัดเจน: *"Do not state a mortality, survival, selection, or fitness cost."*

### 3.2 ทำไมมันฆ่าเปเปอร์

คำค้านที่จะเจอแน่ ๆ จากผู้ทรงคุณวุฒิ:

| คำค้าน | สถานะปัจจุบัน |
|---|---|
| "การจัดอันดับผิดในตารางค่า แปลว่าอะไรในเชิงชีวภาพ?" | **ตอบไม่ได้** |
| "ถ้า agent ไม่เคยตายจากมัน แล้วทำไมต้องสนใจ?" | **ตอบไม่ได้** |
| "อันนี้ก็แค่ perceptual aliasing ที่รู้กันตั้งแต่ Whitehead & Ballard 1991" | ตอบได้แค่ครึ่งเดียว (เรามีขอบเขตวิเคราะห์ แต่ไม่มีผลทางนิเวศ) |

ข้อสุดท้ายคือข้อที่อันตรายที่สุด ตราบใดที่ผลลัพธ์จบที่ "ตัวเลขในหน่วยความจำผิด" งานเราคือ **การสาธิตซ้ำของสิ่งที่ทฤษฎีทำนายอยู่แล้ว** สิ่งที่ทำให้มันเป็นงานใหม่คือการแสดงว่า **ความปลอดภัยที่มาเป็นช่วง ๆ สร้างกับดักที่มีต้นทุนจริง** — ซึ่งต้องวัดในนิเวศที่ตายได้เท่านั้น

### 3.3 นิยาม "ปิดแล้ว"

G1 ปิดเมื่อมีครบทั้ง 4 ข้อ:

1. รัน **นิเวศเต็ม** (เดินจริง หาอาหารจริง ตายได้จริง) ที่เปิด `--mortal --starvation-death --aging --toxin-damage-coeff`
2. มีแขน **ควบคุมพิษเท่ากัน (matched-mean-potency)** — ไม่ใช่แค่เทียบกับ "ไม่มีพิษ" (ดู §3.4)
3. รายงานผลแบบจับคู่ seed ≥ 20 seeds พร้อมช่วงความเชื่อมั่นและ effect size
4. ผลออกมาทางใดทางหนึ่ง **แล้วเขียนตามนั้น** ไม่ว่าจะยืนยันหรือหักล้างสมมติฐาน

### 3.4 กับดักการออกแบบที่ต้องกันไว้ก่อน (สำคัญที่สุดในเอกสารนี้)

ถ้าเทียบแค่ "ไม่มีผลไม้พิษ" กับ "ผลไม้พิษเป็นช่วง ๆ" ผลจะออกมาแน่นอนว่าแบบหลังแย่กว่า — **แต่นั่นพิสูจน์แค่ว่าพิษเป็นพิษ ไม่ได้พิสูจน์ว่า "การซ่อนสถานะ" คือสาเหตุ**

ต้องมีแขนที่ **ปริมาณพิษเฉลี่ยต่อการเจอเท่ากัน แต่ไม่มีสถานะซ่อน**:

| แขน | พิษเฉลี่ยต่อการเจอ | มีสถานะซ่อน? | บทบาท |
|---|---|---|---|
| A0 ไม่มีผลไม้พิษ | 0 | – | ฐาน |
| A1 พิษคงที่เต็มกำลัง | สูง | ไม่มี | ขอบบน |
| A2 **พิษเป็นช่วง (detox ตามอายุ)** | p̄ | **มี** | แขนทดลอง |
| A3 **พิษคงที่ระดับ p̄** | **p̄ (เท่า A2)** | ไม่มี | **แขนชี้ขาด** |

> **ข้ออ้างที่ถูกต้องคือ A2 แย่กว่า A3** ทั้งที่กินพิษเฉลี่ยเท่ากัน → ต้นทุนมาจาก **ความซ่อนเร้น ไม่ใช่ปริมาณพิษ**
> ถ้า A2 ≈ A3 → สมมติฐาน "กับดัก" **ถูกหักล้าง** → ต้องเขียนว่า lure เป็นปรากฏการณ์ระดับการแทนค่า ไม่ใช่ระดับนิเวศ และลดข้ออ้างลงมาที่เดิม

### 3.5 ความเสี่ยงและแผนสำรอง

| ความเสี่ยง | ความน่าจะเป็น | แผนสำรอง |
|---|---|---|
| ประชากรสูญพันธุ์ก่อนเห็นผล (ปัญหาค้างเก่า ~tick 549) | **สูง** | ออกแบบเป็น **cohort survival** ไม่ใช่ population persistence — วัดอายุขัยของ founder cohort ไม่ต้องพึ่งการอยู่รอดข้ามรุ่น (ดู E1 ในไฟล์คู่) |
| ความหิวบังคับให้กินทุกอย่าง (`diet_starvation_energy`) กลบการเลือก | กลาง | รายงาน % ของมื้อที่เกิดใต้เพดานความหิว เป็นตัวแปรร่วม และทำ sensitivity 2 ค่า |
| effect เล็กเกินจนไม่มีนัยสำคัญ | กลาง | เพิ่ม seeds เป็น 30 (ตัดสินใจ **ก่อน** ดูผล ตาม prereg) แล้วรายงานตามจริง |

### 3.6 แม้ปิดแล้วก็ยังห้ามอ้าง

- ห้ามอ้าง "วิวัฒนาการ" จาก E1 (เป็นผลภายในชั่วอายุ) → เป็นงานของ G5
- ห้ามอ้างว่าต้นทุนนี้เกิดในสัตว์จริง → เป็นแบบจำลอง

## 4. G2 — ไม่มีแขน "แก้แล้วหาย" (rescue arm)

### 4.1 อาการ

ต้นฉบับ §5.5 เขียนไว้ว่า *"ถ้าเปลี่ยน key เป็น (ชนิด, อายุ) ก็จะแยกได้"* — แต่นี่เป็น **การอภิปราย ไม่ใช่ผลการทดลอง** โค้ดจริงยังเป็น:

```
agents/agent.py:134   food_value_memory: dict[str, float]      # key = ชนิดเท่านั้น
agents/agent.py:1183  _learn_food_value(env, kind, energy)     # ไม่รับ resource → ไม่เห็นอายุ
agents/agent.py:1144  _food_worth_eating(env)                  # เทียบด้วย kind
```

### 4.2 ทำไมมันสำคัญ

ผลลบเดี่ยว ๆ ("ตัวเรียนรู้ทำไม่ได้") อ่อนเสมอ เพราะอธิบายได้หลายทาง — ตัวเรียนรู้ห่วย, พารามิเตอร์ผิด, งานยากเกินไปโดยธรรมชาติ
**ผลลบ + ผลบวกที่ต่างกันแค่ตัวแปรเดียว** คือหลักฐานเชิงสาเหตุ: *ข้อมูลที่ขาดคือสาเหตุ ไม่ใช่ความห่วยของกลไก*

และนี่คือจุดที่ตอบคำวิจารณ์อาจารย์ได้ตรงที่สุด — มันเปลี่ยนเรื่องจาก "เราเอา RL มาเทียบกัน" เป็น "เราระบุ **ข้อมูลขั้นต่ำ** ที่สิ่งมีชีวิตเทียมต้องมี เพื่อรับมือพิษที่เปลี่ยนตามเวลา"

### 4.3 นิยาม "ปิดแล้ว"

ปิดเมื่อรัน 4 แขนบนโลกเดียวกัน seed เดียวกัน ต่างกันแค่ **คีย์ของหน่วยความจำค่าอาหาร**:

| แขน | คีย์ | คาดการณ์ (detox แบบเส้นตรง) | คาดการณ์ (หน้าต่าง พิษ→ปลอด→พิษ) |
|---|---|---|---|
| B1 type-only | `kind` | ถูกล่อ กินพิษต่อ | ถูกล่อ, P(กิน) แบนราบทุกอายุ |
| B2 **type × age** | `kind@age_bin` | แยกได้ พิษ→~0 | **แยกหน้าต่างได้** |
| B3 **sham key** | `kind@random_bin` | ไม่ดีขึ้น | ไม่ดีขึ้น |
| B4 age-aware oracle | กฎตายตัว (ไม่เรียนรู้) | เพดานบน | เพดานบน |

**B3 (sham key) คือแขนที่ขาดไม่ได้** เพราะการเพิ่มคีย์ทำให้ agent "ชิมของใหม่" มากขึ้นโดยอัตโนมัติ (กฎ *ชนิดที่ไม่รู้จัก ให้ชิมหนึ่งครั้ง*) ถ้าไม่มี B3 ผู้ทรงคุณวุฒิจะบอกว่า *"B2 ดีขึ้นเพราะสำรวจมากขึ้น ไม่ใช่เพราะได้ข้อมูลอายุ"* — B3 มีจำนวนคีย์เท่า B2 แต่คีย์ไม่มีข้อมูล จึงตัดคำอธิบายนั้นทิ้ง

### 4.4 จุดที่จะพังได้

| ปัญหา | วิธีจัดการ |
|---|---|
| `best_known = max(ค่าทั้งหมด)` → เพิ่มคีย์แล้วเพดานเปลี่ยน → เกณฑ์ pickiness ขยับ | ต้องรายงานค่า `best_known` ต่อแขน และทำ sensitivity ที่ pickiness 2 ค่า |
| จำนวน bin เป็นพารามิเตอร์ที่ปรับให้ผลสวยได้ | **ตรึงขนาด bin ล่วงหน้าใน prereg** และรายงานทุกค่าที่ลอง ไม่ใช่เฉพาะค่าที่ดี |
| อายุที่ agent "เห็น" = oracle หรือเปล่า | ต้องเขียนตรง ๆ ว่า **นี่คือการให้ cue ที่สมบูรณ์** = ขอบบนทางทฤษฎี ไม่ใช่การอ้างว่า agent รับรู้อายุได้เอง |

### 4.5 แม้ปิดแล้วก็ยังห้ามอ้าง

- ห้ามอ้างว่า agent "ค้นพบ" ว่าอายุสำคัญ — เราเป็นคนใส่ให้
- ห้ามอ้างว่า representation นี้วิวัฒน์ขึ้นมาเอง

## 5. G3 — ไม่มีตัวหารการเผชิญ (exposure denominator)

### 5.1 อาการ

ตัวแปรตามหลักของ Study 1 คือ **"จำนวนมื้อของอาหารค่าต่ำต่อรัน"** ซึ่งเอกสารเองยอมรับใน §3.2.3 ว่า *"The meal outcome is not exposure-normalized"* ปัญหาคือ:

```
จำนวนมื้อ = (จำนวนครั้งที่เจอ) × (ความน่าจะเป็นที่จะยอมกิน)
```

เมื่อ agent เริ่มข้ามอาหาร เส้นทางเดินของมันเปลี่ยน → จำนวนครั้งที่เจอก็เปลี่ยนตาม → **ตัวเลข 1,945 → 423 ปนกันระหว่าง "เลือกน้อยลง" กับ "เจอน้อยลง"**

ปัจจุบันมี `_record_skipped_food` บันทึกการข้าม (265,347 ครั้ง) แต่ **ไม่มีตัวหาร** คือไม่รู้ว่าเจอทั้งหมดกี่ครั้ง และไม่รู้ว่าตอนเจอนั้นอาหารอายุเท่าไร

### 5.2 นิยาม "ปิดแล้ว"

ปิดเมื่อ:

1. ทุกครั้งที่ agent ยืนบนช่องอาหารที่กินได้ ถูกนับเป็น **1 การเผชิญ** พร้อมบันทึก `(ชนิด, อายุ, ศักยภาพพิษ, ตัดสินใจ, ค่าที่เรียนรู้, พลังงานขณะนั้น)`
2. ตัวแปรตามหลักเปลี่ยนเป็น **`P(กิน | เจอ)`** และสำหรับงานพิษคือ **`P(กิน | เจอ, ช่วงอายุ)`**
3. จำนวนมื้อดิบถูกลดชั้นเป็นตัวแปรรอง

### 5.3 ผลพลอยได้ที่สำคัญ

`P(กิน | อายุ)` **คือกราฟที่ design doc เดือน ก.ค. ทำนายไว้ตั้งแต่ต้นว่า "กราฟจะออกมาแปลก"**:

## 6. G4 — ทดสอบระบบนิเวศเดียว

### 6.1 อาการ

Study 1 รันใน regime เดียว: โลก 100×100, ประชากร 50, `--food-energy-mult 50 --drain-mult 0.05`, ปิดการตาย ไม่มีการเกิด นั่นคือ **โลกที่พลังงานล้นเหลือและไม่มีใครตาย** ซึ่งเลือกมาเพื่อแยกกลไกออกจากความหิว — เหตุผลถูกต้อง แต่ทำให้ข้อสรุปผูกกับ config เดียว

### 6.2 คำค้านที่จะเจอ

> "ผลนี้จะเหลืออยู่ไหมถ้าอาหารขาดแคลน? เพราะตอนอาหารขาด การกินของค่าต่ำอาจเป็นกลยุทธ์ที่ถูก"

คำค้านนี้ **แรงเป็นพิเศษกับงานพิษ** เพราะกับดักของเราขึ้นกับการที่ agent มีทางเลือกอื่น ถ้าไม่มีอะไรกินเลย การกินผลไม้มีพิษอาจถูกต้องจริง ๆ → กับดักหายไปเอง นี่คือ **เงื่อนไขขอบเขตที่น่าสนใจ ไม่ใช่จุดอ่อน** ถ้าเราวัดมัน

### 6.3 นิยาม "ปิดแล้ว"

ปิดเมื่อทำซ้ำการทดลองหลัก (E1) ใน **≥2 regime ที่ตรึงไว้ก่อนรัน**:

| Regime | นิยาม | เหตุผล |
|---|---|---|
| R-A "พลังงานเหลือ" | ใกล้ config เดิม (อาหารมาก) | เทียบเคียงกับผลที่มีอยู่ |
| R-B "อาหารจำกัด" | ลดอัตราเกิดอาหาร / โลกเล็กลง / drain ปกติ | ทดสอบว่ากับดักอยู่รอดใต้แรงกดดัน |

พร้อมระบุ **ทิศทางที่คาดการณ์ไว้ล่วงหน้า**: กับดักควร **อ่อนลง** เมื่ออาหารขาด (เพราะเพดาน `diet_starvation_energy` บังคับให้กินทุกอย่างอยู่แล้ว) — ถ้าผลกลับกัน ต้องอธิบาย ไม่ใช่เงียบ

### 6.4 แผนสำรอง

ถ้าเวลาไม่พอสำหรับ 2 regime × 4 แขน × 20 seeds → ทำ regime ที่สองด้วย **แขนน้อยลง (A2 vs A3 เท่านั้น)** และเขียนว่าเป็น transfer test แบบจำกัด ดีกว่าไม่มีเลย

## 7. G5 — ไม่มีวิวัฒนาการ/การคัดเลือก

### 7.1 อาการ และสิ่งที่มีอยู่แล้วโดยไม่รู้ตัว

ทั้งเปเปอร์ไม่มีการคัดเลือกข้ามรุ่นเลย **ทั้งที่ชิ้นส่วนครบแล้ว**:

| ชิ้นส่วน | ที่อยู่ | สถานะ |
|---|---|---|
| ยีน `toxin_tolerance` ถ่ายทอดได้ ช่วง (0,1) ค่าเริ่ม 0.2 | `agents/body.py:99,164,192,231` | **มีแล้ว** |
| ความเสียหายเรื้อรังจากพิษสะสมเข้า `damage` | `agents/agent.py:1194` `_apply_toxin` | **มีแล้ว** |
| `damage` ทำให้ตายจริง (Aging Physics v1) | `--aging` | **มีแล้ว** |
| การถ่ายทอดยีนกลุ่ม metabolism | `agents/agent.py:631` | **ต้องใช้ `--model v2` เท่านั้น** |

### 7.2 อุปสรรคจริง 2 ข้อ (ตรวจโค้ดแล้ว)

**(1) ยีนนี้มองไม่เห็นใน telemetry** — `body.trait_values` คืนเฉพาะ `TRAIT_FIELDS` (13 ยีนคลาสสิก) ส่วน `toxin_tolerance` อยู่ใน `METABOLISM_TRAIT_FIELDS` ซึ่ง **ไม่ถูกส่งออกทั้งใน `agent_outcomes.csv` และ `generation_traits.csv`** → ตอนนี้ต่อให้รันก็ **วัดการคัดเลือกไม่ได้** ต้องแพตช์ telemetry ก่อน (งานเล็ก แต่เป็น precondition)

**(2) ประชากร mortal ยังสูญพันธุ์** — ตาม `research_summary_2026-06-30.en.md` ปัญหานี้ **ยังไม่ปิด**: ตัวอย่างฐานสูญพันธุ์ที่ tick 549 (peak 148, เกิด 114, ตาย = 123 หมดอายุขัย / 37 อดอาหาร / 4 ความทนทาน) สาเหตุถูกจำกัดวงไว้ที่ความตึงเครียด clustering ⟂ dispersal ซึ่งเป็นคนละงานกับเปเปอร์นี้

> **ห้ามผูกชะตาเปเปอร์พิษไว้กับการแก้ปัญหาประชากร** นั่นเป็นงานวิจัยอีกชิ้นหนึ่ง

### 7.3 นิยาม "ปิดแล้ว" — สองระดับ ให้เลือกตามที่ทำได้จริง

| ระดับ | ข้ออ้าง | ต้องใช้อะไร | ความเป็นไปได้ |
|---|---|---|---|
| **N1 — selection differential** (ขั้นต่ำ) | "พิษเป็นช่วง ๆ สร้าง**แรงกดดันคัดเลือก**ต่อ `toxin_tolerance`" | แค่ founder cohort อยู่นานพอให้ตายแบบเลือกเฟ้น — **ไม่ต้องข้ามรุ่น** | **สูง** |
| **N2 — response to selection** (เต็ม) | "ค่าเฉลี่ยของยีน**ขยับข้ามรุ่น**" | ประชากรต้องรอด ≥5–10 รุ่น | **ต่ำ** (ติดปัญหาค้าง) |

**N1 คือเป้าหมายของแผนนี้** วัดด้วย selection differential `S = ค่าเฉลี่ยยีนของผู้รอด − ค่าเฉลี่ยยีนของ founder ทั้งหมด` และความแปรปรวนร่วมระหว่างยีนกับอายุที่ตาย/จำนวนลูก
N2 เป็น **เป้าเสริม**: ถ้ารันยาวแล้วประชากรบังเอิญรอด ก็รายงานเป็นผลเสริม ถ้าไม่รอด **รายงานว่าไม่รอด** และอ้างแค่ N1

### 7.4 เหตุผลที่คุ้มทำ

*Artificial Life* เป็นวารสารที่ให้น้ำหนักกับการจัดระเบียบตัวเองและวิวัฒนาการ การมีประโยคว่า *"กับดักนี้สร้างแรงกดดันคัดเลือกที่วัดได้ต่อยีนความทนพิษ"* เปลี่ยนงานจาก "กรณีศึกษาเรื่อง representation" เป็น "กลไกทางนิเวศ-วิวัฒนาการ" ซึ่งตรงกับขอบเขตวารสารมากกว่ามาก

### 7.5 ถ้า S ≈ 0

รายงานตรง ๆ ว่า **ในช่วงพารามิเตอร์ที่ทดสอบ กับดักไม่สร้างแรงคัดเลือกที่ตรวจจับได้** พร้อมคำอธิบายเชิงกลไก (เช่น ความเสียหายเรื้อรังเล็กเกินเทียบกับสาเหตุการตายอื่น) — นี่ยังเป็นผลที่มีค่า เพราะมันบอกเงื่อนไขที่กับดักจะ *ไม่* สำคัญ

## 8. G6 — deferral / เก็บอาหารไว้ให้หายพิษ

### 8.1 สถานะ

`design_store_to_detoxify_2026-07-01.th.md` วิเคราะห์ไว้แล้วว่าทำไมมัน **ไม่น่า emerge** จากระบบปัจจุบัน: การเรียนรู้เป็น EMA ของรางวัล **ทันที** ต่อชนิด จึงให้เครดิตรางวัลที่มาทีหลังไม่ได้ (temporal credit assignment) การจะได้ deferral ต้องมีอย่างน้อย 4 อย่าง:

1. ชิ้นอาหารมีตัวตนคงอยู่และมีอายุ
2. การกระทำที่เลื่อนเวลาการกินได้ (เก็บ)
3. วิธีเชื่อมผลที่เกิดทีหลังกลับมายังการตัดสินใจตอนเก็บ
4. นโยบายที่ชั่งน้ำหนักโอกาสตอนนี้กับค่าในอนาคต

### 8.2 คำตัดสิน: **ไม่ทำในรอบนี้**

เหตุผล:

- เป็นงานสร้างกลไกใหม่ ไม่ใช่การเก็บหลักฐานของข้ออ้างที่มีอยู่
- `SUBMISSION_BLOCKERS.md` สั่งห้ามอ้างอยู่แล้ว: *"Do not claim that storing or deferring food emerged"*
- ถ้าใส่เข้าไปครึ่ง ๆ กลาง ๆ จะกลายเป็นจุดอ่อนที่ผู้ทรงคุณวุฒิเจาะ

### 8.3 วิธีใช้ประโยชน์จากมันโดยไม่ต้องทำ

เขียนเป็น **ส่วน "การทดลองถัดไป" ที่เจาะจง** พร้อมเงื่อนไข 4 ข้อข้างบน — ส่วน future work ที่ระบุกลไกได้ชัดขนาดนี้ทำให้เปเปอร์ดูมีทิศทาง ไม่ใช่จบแบบลอย ๆ และผลจาก E2 (rescue arm) จะเป็น **เหตุผลรองรับ** ว่าทำไมขั้นต่อไปต้องเป็น deferral: เพราะเราแสดงแล้วว่าแค่เพิ่มข้อมูลอายุก็พอสำหรับ "เลือกกินของที่แก่แล้ว" แต่ **ยังไม่พอสำหรับ "เก็บของสดไว้กินทีหลัง"**

### 9.1 R6 — วรรณกรรมที่เรายังไม่แตะ และควรเป็นบ้านของงานนี้

Introduction ปัจจุบันวางงานไว้ในสาย **perceptual aliasing / POMDP** ซึ่งเป็นสายที่ **งานเราตามหลังเขา 30 ปี** เราจึงดูเหมือนสาธิตซ้ำ

แต่ปรากฏการณ์ที่เราสร้างขึ้นคือสิ่งที่นิเวศวิทยาเรียกว่า **กับดักทางนิเวศ (ecological trap)** — สถานการณ์ที่สัญญาณซึ่งเคยเชื่อถือได้ นำสิ่งมีชีวิตไปสู่ทางเลือกที่แย่ ถ้าวางงานไว้ตรงนี้:

- เราไม่ได้แข่งกับ POMDP แต่เรา **มีส่วนร่วม** โดยเป็น *แบบจำลองสังเคราะห์ของกับดักที่เกิดจากความแปรผันเชิงเวลาภายในชนิดเดียว* พร้อม **ขอบเขตเชิงวิเคราะห์** `p* = (V_a − V_s)/(V_a − V_f)` ที่ทำนายว่ากับดักจะเกิดเมื่อไร
- E1 (ต้นทุนจริง) + E3 (แรงคัดเลือก) กลายเป็น **หัวใจ** ไม่ใช่ส่วนเสริม เพราะวรรณกรรมกับดักสนใจต้นทุนต่อ fitness โดยตรง

**คำเตือนตามกฎของโปรเจกต์:** ชื่อสายวรรณกรรมข้างบนเป็น **ทิศทางการค้น ไม่ใช่การอ้างอิงที่ตรวจสอบแล้ว** ต้องไปอ่านฉบับจริง ยืนยันผู้แต่ง/ปี/เนื้อหา และ **ห้ามใส่ลงต้นฉบับก่อนอ่านจริง** (บทเรียนจาก R3 และจากการแก้ผู้แต่ง Touzani et al. 2010 ในรอบที่แล้ว)

## 12. สิ่งที่ยัง **ห้ามอ้าง** แม้ปิด G1–G5 ครบ

รายการนี้ต้องคัดลอกลงส่วน Limitations ของต้นฉบับใหม่:

1. ✗ agent **เข้าใจ**ว่าอาหารเป็นพิษ — มันมีแค่ตัวเลขจากประสบการณ์
2. ✗ agent **ค้นพบ**ว่าอายุเป็นตัวแปรสำคัญ — ในแขน B2 เราเป็นคนใส่ให้
3. ✗ การถ่ายทอดความรู้ทางสังคม — ยังเป็นการเรียนรู้ส่วนบุคคลล้วน
4. ✗ กฎการเรียนรู้วิวัฒน์ขึ้นเอง — กฎถูกตรึงไว้ทุกแขน
5. ✗ การเก็บ/เลื่อนการกิน (G6)
6. ✗ วิวัฒนาการแบบเปิดปลาย หรือประชากรที่ยั่งยืนข้ามรุ่น — **ยังเป็นปัญหาค้างของโปรเจกต์**
7. ✗ ความสอดคล้องเชิงปริมาณกับสัตว์จริง — ขอบเขต `p* = 0.625` ผูกกับค่าพลังงานที่เราเลือก ไม่ใช่ค่าคงที่ทางชีววิทยา

## 13. สรุปหนึ่งย่อหน้า

ฉบับ 1 ก.ย. เป็นต้นฉบับที่เขียนดีแต่หลักฐานยังเท่าเดิม อาจารย์ชี้ถูกว่าส่วนเรียนรู้ทั่วไปไม่ใช่จุดขาย และส่วนพิษคือของจริง แผนนี้จึงนิยาม "ของจริง" ให้วัดได้: **พิษที่มา-หาย-มา สร้างกับดักที่มีต้นทุนทางนิเวศ (G1) ซึ่งแก้ได้ด้วยการเพิ่มข้อมูลขั้นต่ำหนึ่งอย่าง (G2) วัดอย่างถูกต้องด้วยตัวหารการเผชิญ (G3) คงอยู่ข้าม regime (G4) และสร้างแรงกดดันคัดเลือกที่ตรวจจับได้ (G5)** ส่วนการเก็บอาหารไว้ให้หายพิษ (G6) เป็นบทต่อไปที่เรารู้แล้วว่าต้องการอะไร วิธีรันทั้งหมดอยู่ในไฟล์คู่ [`PLAN_E1_E6_experiments_2026-09-12.th.md`](PLAN_E1_E6_experiments_2026-09-12.th.md)
