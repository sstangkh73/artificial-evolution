```
E6 (prereg)  →  E0 (pilot calibrate)  →  E4 (ตัวหาร)  →  E1 (ต้นทุน)  →  E2 (rescue)  →  E5 (regime 2)  →  E3 (คัดเลือก)
```

## 2. แพตช์ที่ต้องเขียน (P0–P3)

> ทุกแพตช์ต้องมาพร้อมการทดสอบ และต้องผ่าน `python -m unittest discover -s tests` ทั้งชุดก่อนรันการทดลองใด ๆ

### P0 — ตัวคูณศักยภาพพิษคงที่ (`toxin_potency_scale`)

**ทำไมต้องมี:** เพื่อสร้างแขน A3 "พิษเฉลี่ยเท่ากันแต่ไม่มีสถานะซ่อน" ซึ่งเป็นแขนชี้ขาดของ E1 (ดู `PLAN_G1_G6` §3.4) การลดค่า `--toxin-acute-penalty` แทน **ใช้ไม่ได้** เพราะ `metabolism.toxin_penalty(load × potency, tolerance)` หักด้วยค่าความทนทานก่อน จึงไม่เป็นเชิงเส้น — ต้องปรับที่ `potency` เท่านั้น

| รายการ | รายละเอียด |
|---|---|
| ไฟล์ | `world/environment.py` (เพิ่มฟิลด์), `agents/agent.py:1194` `_apply_toxin` |
| ค่าเริ่มต้น | `1.0` → byte-identical |
| ตรรกะ | เมื่อโหมด detox และ window ปิดทั้งคู่ ใช้ `potency = toxin_potency_scale` แทน `1.0`; เมื่อโหมดใดเปิด ให้ **คูณทับ** ผลจาก `toxin_age_potency` |
| CLI | `--toxin-potency-scale` ใน `scripts/food_value_study_driver.py` |
| เทสต์ | `test_potency_scale_default_is_one`, `test_potency_scale_matches_mean_of_detox_profile` |

## 3. E0 — Pilot calibration (ไม่นับเป็นผล ห้ามอ้างอิง)

**วัตถุประสงค์:** หาค่าพารามิเตอร์ที่ทำให้การทดลองมีความหมาย **ก่อน** ตรึงใน E6 — ไม่ใช่การหาค่าที่ทำให้ผลสวย

| สิ่งที่ต้องหา | เกณฑ์ |
|---|---|
| `--toxic-food` (อัตราเกิดผลไม้พิษ) | agent เฉลี่ยต้องเจอผลไม้ ≥30 ครั้ง/ชีวิต มิฉะนั้นเรียนรู้ไม่ทัน |
| `--toxin-acute-penalty` | ต้องทำให้ค่าที่เรียนรู้ของผลไม้สด **ต่ำกว่า** อาหารหลัก แต่ค่าเฉลี่ยผสม **สูงกว่า** (เงื่อนไขของกับดัก) |
| `--toxin-damage-coeff` | ต้องทำให้ความเสียหายจากพิษเป็นสัดส่วนที่เห็นได้ของ `damage` รวม — วัดจาก `toxin_damage_total / damage` |
| `--toxin-detox-ticks` | ต้องนานพอให้ผลไม้ "สด" มีจริงในโลก (เทียบกับอายุเฉลี่ยของอาหารบนพื้น) |
| p̄ (ศักยภาพพิษเฉลี่ยที่เกิดขึ้นจริง) | **ต้องวัดจากรันจริง** ไม่ใช่คำนวณจากทฤษฎี เพราะอายุของผลไม้ตอนถูกกินเป็นผลพวงของพฤติกรรม → ใช้ตั้งค่า A3 |
| ระยะเวลารัน | 1 seed จับเวลาจริง → ประเมินเวลารวมของ E1–E5 |
| การอยู่รอดของ founder cohort | ต้องมี agent รอด ≥30% ที่ tick กลางรัน มิฉะนั้นวัดความต่างไม่ได้ |

**ผลผลิต:** `reports/E0_calibration_notes_<วันที่>.th.md` + ตารางเวลาที่วัดจริง
**กฎ:** ตัวเลขจาก E0 **ห้ามปรากฏในต้นฉบับ** เป็นผลการทดลอง

## 4. E1 — ต้นทุนของกับดักในนิเวศเต็ม (การทดลองหลัก)

### 4.1 คำถามและสมมติฐาน

**คำถาม:** ความเป็นพิษที่ *ซ่อนอยู่ในอายุของอาหาร* ทำให้สิ่งมีชีวิตเทียมเสียหายมากกว่าความเป็นพิษปริมาณเท่ากันที่ *คงที่และเรียนรู้ได้* หรือไม่

| # | สมมติฐาน | คำทำนาย | หักล้างเมื่อ |
|---|---|---|---|
| **H1.1** | พิษเป็นช่วงสร้างต้นทุนสูงกว่าพิษคงที่ที่ปริมาณเฉลี่ยเท่ากัน | A2 อยู่รอดสั้นกว่า A3 อย่างมีนัยสำคัญ (จับคู่ seed) | A2 ≈ A3 หรือ A2 ดีกว่า |
| **H1.2** | ต้นทุนมาจากการ *เลือกกิน* ไม่ใช่การบังเอิญเจอ | `P(กิน \| เจอผลไม้)` ของ A2 สูงกว่า A3 ที่ระดับการเผชิญเท่ากัน | P(กิน) เท่ากันทั้งสองแขน |
| **H1.3** | ค่าที่เรียนรู้ของ A2 ลู่เข้าใกล้ค่าเฉลี่ยผสม ไม่ใช่ค่าจริงด้านใดด้านหนึ่ง | `food_value_memory["raw_fruit"]` ของ A2 อยู่ใกล้ `V_mix` และ **สูงกว่า** ค่าอาหารหลัก | ค่าลงเอยต่ำกว่าอาหารหลัก (= หลีกเลี่ยงสำเร็จ) |
| **H1.4** | พิษคงที่เต็มกำลังเรียนรู้ให้หลีกเลี่ยงได้ (positive control) | A1 มี `P(กิน\|เจอ)` ลดลงตามเวลาจนต่ำ | A1 ไม่ลด → กลไกการเรียนรู้มีปัญหา ต้องหยุดและตรวจสอบ |

### 4.2 แขนการทดลอง

| แขน | `--toxic-food` | `--toxin-detox-ticks` | `--toxin-potency-scale` | สถานะซ่อน | บทบาท |
|---|---|---|---|---|---|
| **A0** | 0 | – | – | – | ฐาน ไม่มีพิษ |
| **A1** | X | 0 (ปิด) | 1.0 | ไม่มี | พิษคงที่เต็มกำลัง |
| **A2** | X | T | 1.0 | **มี** | **แขนทดลอง** |
| **A3** | X | 0 (ปิด) | **p̄ จาก E0** | ไม่มี | **แขนชี้ขาด** |

> A2 vs A3 คือการเปรียบเทียบที่เปเปอร์ตั้งอยู่บนมัน ทุกอย่างเท่ากันหมด ต่างแค่ *พิษกระจายตัวยังไง* — A3 ได้พิษ p̄ ทุกคำแบบคาดเดาได้ ส่วน A2 ได้ 0 หรือเต็มแบบสุ่มตามอายุที่มองไม่เห็น โดยมีค่าเฉลี่ยเท่ากัน

### 4.3 ตัวแปร

- **ตัวแปรอิสระ:** รูปแบบการกระจายของพิษ (4 ระดับข้างบน)
- **ตัวแปรตามหลัก (ตัวเดียว):** **อายุเฉลี่ยตอนตายของ founder cohort** (จาก `agent_outcomes.csv` คอลัมน์ `age`) — เลือกตัวนี้เพราะไม่ขึ้นกับการรอดของประชากรข้ามรุ่น ซึ่งเป็นปัญหาค้างที่ยังไม่แก้
- **ตัวแปรตามรอง:** สัดส่วนที่รอดถึง tick กลางรัน · `toxin_damage_total` ต่อ agent · `toxin_ingested_total` · `damage` รวม · `P(กิน | เจอผลไม้)` (จาก P3) · สัดส่วนมื้อที่กินใต้เพดาน `diet_starvation_energy` · จำนวนเกิด · `food_value_memory_json` ตอนจบ · การกระจายของ `death_reason`
- **ตัวแปรควบคุม:** seed, ขนาดโลก, ประชากรตั้งต้น, body index, `--pickiness`, `--starvation-energy`, พารามิเตอร์ aging ทั้งชุด, `--model`

### 4.4 การออกแบบที่เลี่ยงปัญหาประชากรสูญพันธุ์

**นี่คือการตัดสินใจออกแบบที่สำคัญที่สุดของ E1**

ปัญหาค้างของโปรเจกต์คือประชากร mortal สูญพันธุ์ (ตัวอย่างฐาน: สูญพันธุ์ tick 549 ตามรายงาน 30 มิ.ย. 2569) ถ้า E1 วัด "ประชากรอยู่รอดกี่ tick" ผลจะถูกกลบด้วยสาเหตุที่ไม่เกี่ยวกับพิษเลย

**ทางออก: วัดที่ founder cohort ไม่ใช่ที่ประชากร**

- ตั้งประชากรเริ่มต้น 50 ตัว เปิด `--mortal --starvation-death --aging`
- **ไม่ต้องพึ่งการเกิด** — ให้การเกิดเป็นตัวแปรตามรอง ไม่ใช่เงื่อนไขของการทดลอง
- ความยาวรันตั้งให้จบ *ก่อนหรือราว ๆ* จุดที่ founder ส่วนใหญ่ตายตามธรรมชาติ (หาจาก E0)
- `--founder-age-spread` > 0 เพื่อกระจายอายุ founder ลดคลื่นการตายพร้อมกัน

ผลที่ได้คือคำถามที่ตอบได้สะอาด: *"ภายในชั่วอายุเดียว การกระจายพิษแบบไหนทำให้สิ่งมีชีวิตตายเร็วกว่ากัน"*

### 4.8 สถิติ

1. คำนวณเมตริกระดับ run (เฉลี่ยข้าม agent ภายใน run)
2. ผลต่างแบบจับคู่ต่อ seed: `D_i = metric(A3, seed i) − metric(A2, seed i)`
3. รายงาน: ค่าเฉลี่ยและ SD ต่อแขน · ค่าเฉลี่ยผลต่างจับคู่ · ช่วงความเชื่อมั่น 95% (t หรือ bootstrap) · **exact two-sided sign-flip test** · **Cliff's delta**
4. การเปรียบเทียบหลักมีคู่เดียว (A2 vs A3) — คู่อื่น (A0, A1) เป็นบริบท ใช้ Holm ถ้าจะทดสอบเชิงยืนยัน
5. ห้ามใช้ Mann–Whitney แบบไม่จับคู่เป็นหลักฐานหลัก (บทเรียนจากการแก้ p-value ครั้งก่อนใน `EVIDENCE.md`)

### 4.9 เกณฑ์สำเร็จ / ล้มเหลว

| ผล | การตีความ | สิ่งที่ต้องทำ |
|---|---|---|
| A2 แย่กว่า A3 อย่างมีนัยสำคัญ | **กับดักมีต้นทุนจริง** | เดินหน้าตามกรอบ ecological trap |
| A2 ≈ A3 | ต้นทุนมาจากปริมาณพิษ ไม่ใช่ความซ่อนเร้น | **เปลี่ยนกรอบ** เป็นผลระดับการแทนค่าเท่านั้น และรายงานผลลบ |
| A2 ดีกว่า A3 | ผิดจากที่คาด | ตรวจ confound (การเผชิญ? ความหิว?) แล้วรายงานตรง ๆ |
| A1 ไม่แสดงการเรียนรู้หลีกเลี่ยง | positive control ล้ม | **หยุด** ตรวจกลไกก่อน ไม่ตีความแขนอื่น |

### 4.10 confound ที่ต้องรายงานเสมอ

- `best_known` เฉลี่ยต่อแขน (เพดานของเกณฑ์ pickiness)

## 5. E2 — แขนกู้คืน: คีย์ (ชนิด × อายุ)

### 5.1 คำถามและสมมติฐาน

**คำถาม:** ข้อมูลขั้นต่ำอะไรที่ทำให้สิ่งมีชีวิตเทียมหลุดจากกับดักได้

| # | สมมติฐาน | คำทำนาย | หักล้างเมื่อ |
|---|---|---|---|
| **H2.1** | คีย์ (ชนิด × อายุ) แก้ปัญหา detox แบบเส้นตรงได้ | B2 มี `P(กิน \| สด)` ต่ำ และ `P(กิน \| แก่)` สูง; พิษที่กิน → ใกล้ 0 | P(กิน) ยังแบนราบ |
| **H2.2** | ผลของ B2 ไม่ได้มาจากการสำรวจที่มากขึ้น | **B3 (sham) ไม่ดีขึ้น** ทั้งที่มีจำนวนคีย์เท่า B2 | B3 ดีขึ้นพอ ๆ กับ B2 → คำอธิบายเป็นการสำรวจ ไม่ใช่ข้อมูล |
| **H2.3** | กรณีหน้าต่าง พิษ→ปลอด→พิษ ฮิวริสติกแบบทางเดียวแก้ไม่ได้ แต่คีย์ต่อช่วงอายุแก้ได้ | B2 ได้ `P(กิน\|อายุ)` เป็นรูปภูเขาตรงหน้าต่าง; แขน "แก่=ปลอดภัย" กินของเน่าปลายทาง | B2 แก้หน้าต่างไม่ได้ → ขนาด bin หรือเพดานมีปัญหา |
| **H2.4** | B2 ยังต่ำกว่าเพดานทฤษฎี | B4 (oracle) ดีกว่า B2 เล็กน้อยเพราะ B2 ต้องเสียค่าชิมเพื่อเรียนรู้ | B2 ≥ B4 → สงสัยว่ามีการรั่วของข้อมูล ต้องตรวจ |

### 5.2 แขนการทดลอง (รันทั้ง 2 โปรไฟล์พิษ)

| แขน | คีย์ | หมายเหตุ |
|---|---|---|
| B1 | `type` | เท่ากับ A2 ของ E1 |
| B2 | `type_age` | แขนกู้คืน |
| B3 | `type_sham` | **ควบคุมจำนวนคีย์** |
| B4 | oracle (กฎตายตัว กินเฉพาะที่ปลอดภัย) | เพดานบน ไม่เรียนรู้ |

**โปรไฟล์พิษ 2 แบบ:**
- **โปรไฟล์ M (เส้นตรง):** `--toxin-detox-ticks T` — "เก็บไว้นานพอ พิษจะจาง"
- **โปรไฟล์ W (หน้าต่าง):** `--toxin-safe-window-start 3 --toxin-safe-window-end 7` — **พิษ → ปลอดภัย → พิษ** ซึ่งคือส่วนที่อาจารย์ชี้ว่าเป็นของเรา

> โปรไฟล์ W สำคัญกว่าในเชิงวิชาการ เพราะมันตัดคำอธิบายง่าย ๆ ที่ว่า *"ก็แค่รอให้มันแก่ก่อนค่อยกิน"* ออกไปทั้งหมด — ใน W "แก่กว่า" ไม่ได้แปลว่า "ปลอดภัยกว่า" ต้องรู้ทั้งเส้นโค้ง (`world/metabolism.py:107` `toxin_age_potency` โหมดหน้าต่างคืน potency 0 เฉพาะใน `[start, end)` และ 1 นอกนั้น)

รวม: 20 seeds × 4 แขน × 2 โปรไฟล์ = **160 รัน**

### 5.3 ตัวแปรตาม

- **หลัก:** `P(กิน | เจอ, สถานะจริงปลอดภัย) − P(กิน | เจอ, สถานะจริงเป็นพิษ)` = **ดัชนีการแยกแยะ** (ใช้ตัวหารจาก P3)
  - โดยนิยาม B1 ต้องได้ ≈ 0 (คีย์เดียวสำหรับทุกอายุ) — เป็นผลระดับการแทนค่า ไม่ใช่การค้นพบเชิงสถิติ ต้องเขียนแบบนี้ในต้นฉบับ
- **รอง:** พลังงานสุทธิต่อผลไม้ที่กิน · สัดส่วนมื้อที่เป็นพิษ · `toxin_damage_total` · อายุตอนตาย · จำนวนคีย์ที่เกิดขึ้นจริงต่อ agent · `best_known`

### 5.4 รูปที่ต้องได้จาก E2

**Figure หลักของเปเปอร์ใหม่:** แกน x = อายุอาหาร · เส้นทึบ = ความจริง (potency ตามอายุ) · เส้นประ = ค่าที่ agent เรียนรู้ · แท่ง/เส้น = `P(กิน | อายุ)` ต่อแขน
รูปเดียวนี้แสดง **ความจริง ความเชื่อ และการกระทำ** พร้อมช่องว่างระหว่างกัน — และในโปรไฟล์ W มันจะเห็นชัดมากว่า B1 แบนราบทับหน้าต่าง ส่วน B2 ขึ้นรูปภูเขาตรงหน้าต่างพอดี

### 5.5 กับดักและวิธีกัน

| กับดัก | วิธีกัน |
|---|---|
| ขนาด bin ปรับจนผลสวย | ตรึงใน E6; ถ้าลองหลายค่า **ต้องรายงานทุกค่า** |
| B2 ชิมมากกว่าเพราะคีย์เยอะ | B3 (sham) คุมไว้แล้ว + รายงานจำนวนการชิมครั้งแรกต่อแขน |
| การให้เห็นอายุ = oracle แอบแฝง | เขียนตรง ๆ ว่าเป็นการ **ให้ cue ที่สมบูรณ์** = ขอบบนทางทฤษฎี ไม่ใช่ข้ออ้างว่า agent รับรู้อายุได้เอง |

### 7.3 ผลที่เป็นไปได้ และสิ่งที่ต้องทำ (จุดตัดสินใจ D1)

| ผล | การตีความ | การกระทำ |
|---|---|---|
| `P(กิน\|เจอ)` ลดลงมากพอ ๆ กับจำนวนมื้อ | ผลเดิมแข็งขึ้น | ใช้ตัวหารเป็นตัวแปรตามหลักในทุกที่ |
| ลดลงบ้างแต่น้อยกว่ามาก | ส่วนหนึ่งของผลเดิมมาจากการเปลี่ยนเส้นทางเดิน | **แก้ไขข้ออ้างของ Study 1** และบันทึกใน `EVIDENCE.md` แบบเดียวกับที่เคยแก้ p-value |
| ไม่ลดเลย | ผลเดิมเป็นผลของการเผชิญล้วน | ลดชั้น Study 1 ลงเป็น supplement — **และเขียนการแก้ไขนี้อย่างเปิดเผย** |

> ผลข้อ 3 คือผลที่เจ็บที่สุด แต่ถ้าเกิดขึ้นจริงแล้วเราไม่รายงาน นั่นคือการทำวิจัยที่ไม่ซื่อสัตย์ กฎของโปรเจกต์ระบุไว้แล้วว่าการแก้ไขที่เปิดเผยคือจุดแข็ง ไม่ใช่จุดอ่อน

## 8. E5 — ทำซ้ำใน regime ที่สอง

### 8.1 นิยาม regime (ตรึงก่อนรัน)

| Regime | พารามิเตอร์ | ความหมาย |
|---|---|---|
| **R-A** | ใกล้ config เดิม (อาหารมาก, `--food-energy-mult` สูง) | มีทางเลือก → กับดักควรทำงาน |
| **R-B** | อาหารจำกัด: ลด `--food-energy-mult` / ลด `--natural-seed-rain` / โลกเล็กลง (`--world 60`) / `--drain-mult` ปกติ | ทางเลือกน้อย → เพดานความหิวบังคับให้กิน |

### 8.2 คำทำนายที่ประกาศล่วงหน้า

> กับดักควร **อ่อนลง** ใน R-B เพราะเมื่ออดอยาก การกินผลไม้ที่อาจมีพิษเป็นการตัดสินใจที่สมเหตุสมผลขึ้น และเพดาน `diet_starvation_energy` จะบังคับให้กินอยู่แล้วโดยไม่สนค่าที่เรียนรู้

นี่ไม่ใช่คำแก้ตัวล่วงหน้า แต่เป็น **การทำนายที่ทดสอบได้** — ถ้าผลกลับด้าน (กับดักแรงขึ้นเมื่ออดอยาก) นั่นคือการค้นพบที่น่าสนใจกว่าเดิม และต้องอธิบายเชิงกลไก

### 8.3 ขอบเขต

รัน **A2 vs A3 เท่านั้น** ใน R-B (ไม่ต้องครบ 4 แขน) × 20 seeds = 40 รัน — เพียงพอสำหรับข้ออ้าง transfer และประหยัดเวลา ถ้าเวลาเหลือค่อยเติม A0/A1

## 9. E6 — Preregistration และการตรึงโปรโตคอล

### 9.1 ทำไมคุ้มมากสำหรับนักเรียนที่ทำคนเดียว

เราไม่มีห้องแล็บหรือชื่อเสียงรองรับ สิ่งที่ทดแทนได้คือ **หลักฐานว่าเราไม่ได้เลือกผลทีหลัง** เอกสาร prereg ที่ commit ไว้พร้อม hash **ก่อน** รันชุดยืนยัน คือหลักฐานนั้น และมีต้นทุนแค่การเขียนหนึ่งไฟล์

### 9.2 สิ่งที่ต้องอยู่ในเอกสาร prereg

1. สมมติฐานทุกข้อพร้อมทิศทางที่ทำนาย (H1.1–H3.3 ข้างต้น)
2. **ตัวแปรตามหลักหนึ่งตัวต่อการทดลอง** และรายการตัวแปรรองทั้งหมด
3. ชุด seed ที่แน่นอน และจำนวนที่ตกลงไว้ พร้อมกฎว่าจะเพิ่มเมื่อใด
4. พารามิเตอร์ทุกตัวที่ตรึง: `--pickiness`, `--starvation-energy`, ขนาด bin ของ P1, `--toxic-food`, `--toxin-*`, พารามิเตอร์ aging, ความยาวรัน
5. วิธีทางสถิติที่จะใช้ (sign-flip, Cliff's delta, ช่วงความเชื่อมั่น) และการจัดการการทดสอบหลายครั้ง
6. **เกณฑ์การหักล้าง** ของทุกสมมติฐาน
7. กฎเรื่อง confound: จะรายงานอะไรเสมอไม่ว่าผลจะออกมาอย่างไร
8. commit hash + เวอร์ชัน Python + OS

### 9.3 ขั้นตอน

```bash
# 1. เขียนเอกสาร
#    reports/PREREG_toxin_ecological_trap_<วันที่>.th.md
# 2. รันเทสต์ทั้งชุดจาก checkout สะอาด แล้วเก็บผลลง prereg
python -m unittest discover -s tests -v
# 3. commit + tag
git add reports/PREREG_toxin_ecological_trap_*.th.md
git commit -m "Preregister the toxin ecological-trap experiments (E1-E5)"
git tag prereg-toxin-trap-<วันที่>
# 4. บันทึก hash ลงในเอกสารเอง แล้ว commit แก้ครั้งเดียว
```

**หลังจากนี้:** ทุกการเบี่ยงเบนจาก prereg ต้องบันทึกในส่วน "การเบี่ยงเบน" พร้อมเหตุผลและวันที่ ไม่ใช่แก้เอกสารเงียบ ๆ
