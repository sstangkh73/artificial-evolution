## 3. S2: ตรวจ Gate ซ้ำและ power analysis (seeds 1050–1099)
รันตาม 03 ข้อ 6.4 ด้วยค่าของเซลล์ที่เลือก จาก commit `f1985ef` (`code_dirty: false`), manifest ครบ 250/250 คำสั่ง:
```
python scripts/run_tool_discovery.py --out data/tool_discovery_pilot_s2_selected --conditions C0 C1 C2 C3 C4 \
  --seeds 1050-1099 --ticks 1600 --set immortal=true --set epsilon=0.05 --set q_init=0
python scripts/analyze_tool_discovery_pilot.py power data/tool_discovery_pilot_s2_selected \
  --out docs/ysc2027_tool_discovery/pilot_s2_power.json
```

**Gate ซ้ำบน S2 (รายงานเท่านั้น ไม่ใช้เลือกค่าใหม่):**
- Gate A: C3 − C0 = 1.477 [1.413, 1.540] ผ่าน; องค์ประกอบ: อาหาร − แรง +1.230 [1.178, 1.284], ต้นทุนการสร้าง −0.173, ต้นทุนการเก็บ −0.074
- Gate B1: 100% ของรัน C0 มีวัตถุผ่านระดับ A (ผ่านง่ายเหมือน S1)
- Gate B2: C3 − C0 ของ `functional_rate` = 0.116 [0.109, 0.124] (C3 0.146, C0 0.030) ผ่าน

**คู่เทียบหลัก C1 − C2 บน S2** (n = 50 คู่):

| ตัวชี้วัด (ต่อ agent-tick ช่วงท้าย) | C1 | C2 | C1 − C2 [95% CI] |
|---|---|---|---|
| อาหารสุทธิ (หลัก) | 0.397 | 0.118 | 0.279 [0.231, 0.331] |
| อาหาร − แรง (ฝั่งการใช้) | 0.495 | 0.396 | 0.099 [0.084, 0.113] |
| ต้นทุนการสร้าง | 0.061 | 0.174 | −0.114 [−0.140, −0.090] |
| ต้นทุนการเก็บ | 0.037 | 0.104 | −0.066 [−0.082, −0.053] |

(0.099 + 0.114 + 0.066 = 0.279 ตรงกับผลต่างหลัก) C1 > C2 ใน 50/50 seeds บนตัวชี้วัดหลัก และ 49/50 บนอาหาร − แรง

ค่า C1 บน S2 (0.397) ใกล้กับ S1 (0.398) ซึ่ง **ไม่ขัดแย้ง** กับการที่ค่าใน S1 ไม่ได้สูงเกินจริงจากการเลือก แต่ S2 ชุดเดียวยืนยันไม่ได้ว่าไม่มี selection bias ส่วน C1 − C2 บน S2 (0.279) สูงกว่าใน S1 (0.221) เพราะ C2 บน S2 ต่ำกว่า (0.118 vs 0.178) ซึ่งอยู่ในช่วงความแปรปรวนระหว่างชุด seed

**Power analysis (03 ข้อ 7):**
- ค่าเฉลี่ยผลต่าง 0.279, SD ของผลต่าง 0.185, dz = 1.511 (bootstrap 95% CI ของ dz [1.34, 1.82])
- dz_safe (เปอร์เซ็นไทล์ 20 ของ bootstrap 10,000 รอบ, `random.Random(0)`) = 1.446
- สูตร Guenther: n = ⌈(3.242 / 1.446)² + 1.92⌉ = 7
- ปัดขึ้นเป็นทวีคูณของ 10 และขั้นต่ำ 50 → n = 50; จำลอง paired t-test 10,000 ครั้งที่ n = 50, dz = 1.446 ได้ power = 1.00 ≥ 0.90
- **จำนวน seed ของรันยืนยัน = 50 (seeds 5000–5049) ทั้ง 5 เงื่อนไข**
- ไม่มีเงื่อนไขหยุดของข้อ 7/9 (dz > 0, dz_safe > 0, n ≤ 2,000)

ข้อสังเกต: power ที่ n = 50 สูงเกินพอสำหรับคู่เทียบหลัก จำนวน 50 มาจากค่าขั้นต่ำที่ตั้งไว้ก่อนรัน ไม่ได้มาจากผลต่างที่เล็ก ค่าขั้นต่ำนี้ช่วยให้คู่เทียบรอง (ซึ่งมีขนาดผลเล็กกว่า เช่น `rebuild_rate`) มีความแม่นยำพอรายงาน CI ได้

`rebuild_rate` ของ C1 − C2 ตัด 1 คู่เพราะรัน C2 seed 1070 ไม่มีการสร้างหลังจากใช้เครื่องมือสำเร็จ (`crafts_after_success` = 0 ตัวหารเป็นศูนย์) ส่วน `reuse_delta` ใน C3 − C0 ตัดครบ 50 คู่ เพราะ C3 (oracle) ไม่มีประวัติผลเสียให้เทียบ จึงไม่มีความหมายสำหรับ C3

**การตีความ `final_tool_use_rate`:** C1 ใช้เครื่องมือในช่วงท้ายน้อยกว่า C2 ทุก seed (8% vs 24% ของ tick) เมื่อรวมกับตารางองค์ประกอบในข้อ 3 แปลว่า learner ที่ได้สัญญาณจริง (C1) เรียนรู้ทั้ง (ก) ใช้วัตถุกลุ่มที่ได้ผลซ้ำ และ (ข) **เลิกสร้างและเลิกใช้วัตถุที่ไม่คุ้ม** ซึ่งเป็นส่วนใหญ่ของผลต่างอาหารสุทธิ ส่วน C2 ที่ได้สัญญาณสุ่มเลือกใช้/สร้างโดยไม่มีข้อมูลจึงจ่ายต้นทุนมากกว่า ทั้งสองอย่างเป็นการเรียนรู้จากผลจริง แต่ (ข) ไม่ใช่ "การค้นพบเครื่องมือ" โดยตรง ดังนั้นรายงานยืนยันต้องแยกสองส่วนนี้ด้วยองค์ประกอบของอาหารสุทธิ และข้อสรุป "ค้นพบเครื่องมือ" ต้องพึ่งหลักฐานฝั่งการใช้ (อาหาร − แรง) และหลักฐานการค้นพบข้างบน ไม่ใช่อาหารสุทธิอย่างเดียว (สอดคล้องกับ 03 ข้อ 8 ที่กำหนดให้ต้องมีหลักฐานหลายด้าน)

**C1 − C4 (H5 ฝั่งการใช้, เชิงพรรณนา):** อาหารสุทธิ 0.010 [0.000, 0.019] (33/50 seeds) ใกล้ศูนย์มาก; `final_tool_use_rate` 0.030 [0.024, 0.035]; `functional_rate` 0.029 [0.023, 0.035] คือการเรียนรู้ด้วยกลุ่มสมบัติ (C1) ใช้เครื่องมือและได้วัตถุที่ใช้ได้มากกว่าการเรียนรู้ด้วยรหัสวัตถุรายชิ้น (C4) แต่ผลต่างบนอาหารสุทธิเล็กมาก ไม่ควรคาดหวังว่า H5 จะชัดในรันยืนยัน

**C1 − C0 (เชิงพรรณนา):** อาหารสุทธิ 1.414 [1.401, 1.426] แต่ส่วนใหญ่เป็นเพราะ C0 สร้างวัตถุแทบทุก tick ที่ว่าง (03 ข้อ 5) ส่วน `functional_per_agent` ของ C0 สูงกว่า C1 (6.98 vs 1.97) เพราะ C0 สร้างจำนวนมาก จึงต้องใช้ `functional_rate` (0.060 vs 0.030) เป็นตัวเทียบ ไม่ใช่จำนวน

## 5. Deviation จาก 03
ไม่มีการเปลี่ยนกฎการตัดสิน ตัวชี้วัดหลัก หรือ grid หลังเห็นผล รายการที่ต้องบันทึก:
1. **ลำดับการปัดเลขใน power (การตีความ ไม่ใช่การเปลี่ยน):** 03 ข้อ 7 ไม่ได้กำหนดชัดว่าปัดเป็นทวีคูณของ 10 ก่อนหรือหลังการจำลอง สคริปต์ปัดก่อน (ขั้นต่ำ 50) แล้วจึงจำลองและเพิ่มทีละ 10 ตัดสินในรอบ 5 ก่อนรัน S2 (ตามคำรีวิวของ Codex) ในผลจริงไม่มีผล เพราะ n สูตร = 7 และ n = 50 ผ่านตั้งแต่ครั้งแรก
2. **ตารางตัวชี้วัดรองบน S2:** 03 ไม่ได้ระบุให้รันการเทียบตัวชี้วัดรองบน S2 แต่ข้อ 5 ให้ "รายงานทุกตัว" จึงรายงานครบทุกตัวที่ 03 ข้อ 5 ระบุ (C1 − C2) ในข้อ 4 ใช้เพื่อวางแผนเท่านั้น ไม่ได้ใช้เลือกค่า
3. **ระยะเวลารัน:** 03 ข้อ 4 ประมาณรันละ 0.2–0.5 วินาที จริงคือ 0.4–3 วินาที (C3 ช้าสุด) ไม่มีผลต่อการออกแบบ
